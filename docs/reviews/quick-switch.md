# Home switching and icon alignment verification, 2026-09-08

Installed native UI `0.74.5-airmouse.7`, Node release `d73ebb2543669454`, and Bluetooth release `776e702d2ae28ced` on the lab
Remote 3. Both pairings, custom names, device order, saved selection, and
configuration were unchanged. Hashes of the effective bond payloads and remote
identity also matched the pre-update values.

Home shortcuts remember whether pointing was enabled. Before switching, the
service stops output and releases held buttons. It resumes pointing once the
selected computer is ready. Paused pointing stays paused.

Selection, reconnection, and activation must finish within three seconds.
Timeout, Off, navigation, closure, service failure, or a newer switch cancels
the pending resume. A failed switch leaves pointing off even if the connection
or activation completes later. Switching through the computer manager also
leaves pointing off.

The icon-only button layout included a ten-pixel gap for an empty label, shifting
its icon five pixels left. The corrected layout centers only visible content.
Back and next chevrons also have centered drawing bounds. Shortcut contents are
centered inside their cards.

## Measured switching times

`tools/airmouse-switch-check` measures from selection command to the native
protocol reporting the chosen computer ready. It requires the app closed and
pointing off, sends selection commands only, and restores the initial selection.

| Computer | Before | Updated, run 1 | Updated, run 2 |
| --- | --- | --- | --- |
| iPad | 1568 ms | 727 ms | 704 ms |
| Desktop | 1499 ms | 252 ms | 346 ms |

Only these two computers were paired during verification. These few measurements
were taken with pointing paused. They do not predict switch times for sleeping
computers or other hosts. No host pointer movement, button press, or scrolling
was generated by the checks.

The first updated iPad switch established its Bluetooth link in 108 ms and became
ready in 646 ms after the daemon began switching. Desktop took 141 ms and 217 ms,
respectively. Link encryption and host subscription still contribute to latency.
The implementation retains one Bluetooth connection at a time.

Reconnect advertising now runs at a fixed 20 ms interval for 30 seconds,
following [Apple's discovery
guidance](https://developer.apple.com/library/archive/qa/qa1931/_index.html).
The daemon announces readiness immediately after the first zero-button report,
and Node sends state changes without waiting for the 500 ms UI heartbeat.
Movement counters do not trigger UI updates.
